# Agent 核心概念与架构

## 1. 什么是 Agent？

### 一句话理解
**Agent = LLM + 循环 + 工具调用 + 自主决策**

普通 AI 对话是"一问一答"。Agent 是"给它一个目标，它自己想办法完成"。

### 用前端思维理解

```
普通 AI 对话（Chatbot）：
  用户输入 → LLM 处理 → 返回结果
  类比：一个普通的 API 请求

AI Agent：
  用户目标 → LLM 规划 → 选择工具 → 执行 → 观察结果 → 继续或结束
  类比：一个 while 循环 + if/else 决策 + 外部 API 调用

  while (任务未完成) {
    const plan = await llm.think(当前状态, 可用工具);
    const result = await execute(plan);
    const observation = await llm.evaluate(result);
    if (observation.isComplete) break;
  }
```

### 一个具体例子

用户说："帮我分析这个 CSV 文件，找出销售额最高的产品，生成一份报告"

```
Agent 的执行过程：
┌──────────────────────────────────────────────────┐
│ Step 1: 思考 → 需要读取 CSV 文件                   │
│         调用 → read_file("sales.csv")             │
│         得到 → 文件内容                             │
├──────────────────────────────────────────────────┤
│ Step 2: 思考 → 需要解析数据并排序                   │
│         调用 → execute_python("分析代码")          │
│         得到 → 排序结果                             │
├──────────────────────────────────────────────────┤
│ Step 3: 思考 → 需要生成报告                        │
│         调用 → write_file("report.md", 内容)      │
│         得到 → 报告文件                             │
├──────────────────────────────────────────────────┤
│ Step 4: 思考 → 任务完成，回复用户                   │
│         输出 → "报告已生成，保存在 report.md"       │
└──────────────────────────────────────────────────┘
```

## 2. Agent 的核心组件

```
                    ┌─────────────┐
                    │   用户输入   │
                    └──────┬──────┘
                           │
                    ┌──────▼──────┐
                    │  Planner    │  规划器：决定下一步做什么
                    │  (LLM)     │
                    └──────┬──────┘
                           │
              ┌────────────┼────────────┐
              │            │            │
       ┌──────▼──────┐ ┌──▼────┐ ┌─────▼─────┐
       │   Memory    │ │ Tools │ │ Knowledge │
       │   记忆      │ │ 工具  │ │  知识库    │
       └──────┬──────┘ └──┬────┘ └─────┬─────┘
              │            │            │
              └────────────┼────────────┘
                           │
                    ┌──────▼──────┐
                    │  Executor   │  执行器：调用工具并返回结果
                    └──────┬──────┘
                           │
                    ┌──────▼──────┐
                    │   输出结果   │
                    └─────────────┘
```

### 2.1 LLM（大脑）

Agent 的核心推理引擎。它负责：
- 理解用户意图
- 规划执行步骤
- 决定调用哪个工具
- 判断任务是否完成

```typescript
// 本质就是调 API
const response = await openai.chat.completions.create({
  model: "gpt-4o",
  messages: [
    { role: "system", content: "你是一个数据分析助手..." },
    { role: "user", content: "分析这个CSV文件" },
    // ... 对话历史
  ],
  tools: [/* 可用工具定义 */],
});
```

### 2.2 Tools（手脚）

让 Agent 能与外部世界交互的能力。工具就是普通的函数，LLM 决定什么时候调用、传什么参数。

```typescript
// 工具定义（本质就是给 LLM 看的函数签名）
const tools = [
  {
    type: "function",
    function: {
      name: "read_file",
      description: "读取文件内容",
      parameters: {
        type: "object",
        properties: {
          path: { type: "string", description: "文件路径" }
        },
        required: ["path"]
      }
    }
  },
  {
    type: "function",
    function: {
      name: "search_web",
      description: "搜索网页",
      parameters: {
        type: "object",
        properties: {
          query: { type: "string", description: "搜索关键词" }
        },
        required: ["query"]
      }
    }
  }
];

// LLM 返回要调用的工具和参数
// { name: "read_file", arguments: { path: "data.csv" } }

// 你负责执行
const result = await executeTool(response.tool_calls[0]);
```

**前端类比**：Tools 就像组件的 props 回调 —— 你定义接口，LLM 决定什么时候触发。

### 2.3 Memory（记忆）

Agent 需要记住之前做了什么，否则每一步都是从头开始。

```
短期记忆（对话上下文）
  └── 当前对话的所有消息
  └── 类比：React state，组件生命周期内有效

长期记忆（持久化存储）
  └── 历史对话总结、用户偏好
  └── 类比：localStorage/数据库，跨会话保留

工作记忆（当前任务状态）
  └── 当前任务的中间结果、待办事项
  └── 类比：useReducer 的 state，任务生命周期内有效
```

### 2.4 Planning（规划）

Agent 不是无脑调用工具，它会先制定计划。

```
ReAct 模式（最常用）：
  Thought: 我需要先读取文件
  Action:  read_file("data.csv")
  Observation: [文件内容]
  Thought: 数据已获取，现在需要分析
  Action:  analyze_data(...)
  ...
```

## 3. Agent 架构模式

### 3.1 ReAct（Reasoning + Acting）

最基础也最常用的模式。LLM 交替进行"思考"和"行动"。

```
用户: "查一下北京今天的天气，然后发邮件告诉我"

Agent 内部循环：
  Thought: 需要先查天气
  Action:  search_weather("北京")
  Observation: "北京今天晴，25°C"

  Thought: 天气已获取，需要发邮件
  Action:  send_email(to="用户", content="北京今天晴，25°C")
  Observation: 邮件发送成功

  Thought: 任务完成
  Final Answer: 已查到天气并发送邮件
```

### 3.2 Plan-and-Execute

先制定完整计划，再逐步执行。适合复杂任务。

```
用户: "帮我重构这个项目的认证模块"

Planner 生成计划：
  Step 1: 分析现有认证代码结构
  Step 2: 设计新的认证方案
  Step 3: 编写新代码
  Step 4: 运行测试
  Step 5: 生成迁移文档

Executor 逐步执行每个步骤
```

### 3.3 Multi-Agent（多 Agent 协作）

多个专业 Agent 各司其职，协同完成复杂任务。

```
┌─────────────┐
│  Supervisor │  调度者：分配任务
└──────┬──────┘
       │
  ┌────┼────┐
  │    │    │
┌─▼─┐┌─▼─┐┌─▼─┐
│ A ││ B ││ C │  专业 Agent：各自执行子任务
│研 ││编 ││测 │
│究 ││码 ││试 │
└───┘└───┘└───┘
```

### 3.4 Workflow（工作流模式）

预定义的 DAG（有向无环图），适合流程固定的场景。

```
        ┌──────┐
        │ 开始 │
        └──┬───┘
           │
     ┌─────▼─────┐
     │ 意图识别   │
     └─────┬─────┘
           │
    ┌──────┼──────┐
    │      │      │
┌───▼──┐┌─▼──┐┌──▼──┐
│查询类││操作类││闲聊类│
└───┬──┘└─┬──┘└──┬──┘
    │     │      │
    └─────┼──────┘
          │
    ┌─────▼─────┐
    │ 生成回复   │
    └───────────┘
```

## 4. Function Calling 详解

这是 Agent 最核心的机制，前端开发者必须深入理解。

### 工作流程

```
┌─────────────────────────────────────────────────────┐
│ 1. 你定义工具（JSON Schema）                          │
│    { name: "get_weather", parameters: {...} }        │
├─────────────────────────────────────────────────────┤
│ 2. 发给 LLM，带上用户消息和工具定义                    │
│    messages: [...], tools: [...]                     │
├─────────────────────────────────────────────────────┤
│ 3. LLM 返回：我要调用哪个工具、传什么参数              │
│    tool_calls: [{ name: "get_weather",              │
│                   arguments: { city: "北京" } }]     │
├─────────────────────────────────────────────────────┤
│ 4. 你的代码执行工具，得到结果                          │
│    result = getWeather("北京") → "晴，25°C"          │
├─────────────────────────────────────────────────────┤
│ 5. 把结果发回 LLM                                    │
│    messages: [..., { role: "tool", content: result }]│
├─────────────────────────────────────────────────────┤
│ 6. LLM 基于结果生成最终回复                           │
│    "北京今天天气晴朗，气温25°C"                        │
└─────────────────────────────────────────────────────┘
```

### 关键点

- **工具是你写的代码**，LLM 只决定调用哪个、传什么参数
- **LLM 不直接执行任何操作**，所有实际操作都是你的代码在做
- **安全边界在你手里**，你可以在执行前做权限校验、参数验证

## 5. RAG（检索增强生成）

Agent 的知识增强手段。解决 LLM "不知道你的私有数据"的问题。

```
传统方式：
  用户: "公司的年假政策是什么？"
  LLM:  "我不知道"（因为训练数据没有你的公司信息）

RAG 方式：
  用户: "公司的年假政策是什么？"
  ↓
  1. 搜索向量数据库，找到相关文档片段
  2. 把片段作为上下文，连同问题一起发给 LLM
  3. LLM 基于上下文生成准确回答

  实际发给 LLM 的：
  System: 根据以下参考资料回答问题：[年假政策文档片段]
  User:   公司的年假政策是什么？
```

### RAG 流程

```
文档处理阶段（离线）：
  PDF/Word/网页
    → 分块（Chunking）
    → Embedding（向量化）
    → 存入向量数据库

查询阶段（在线）：
  用户问题
    → Embedding
    → 向量数据库搜索相似文档
    → 拼接上下文
    → 发给 LLM
    → 生成回答
```

## 6. Agent 开发的核心挑战

### 6.1 可靠性
LLM 输出不是确定性的，同样的输入可能得到不同的输出。需要：
- 输出格式校验（JSON Schema）
- 重试机制
- 兜底策略

### 6.2 安全性
Agent 能执行代码和调用 API，需要严格控制：
- 工具调用权限（哪些工具可用）
- 参数校验（防止注入攻击）
- 执行沙箱（限制文件/网络访问）
- 人工确认（关键操作前让用户确认）

### 6.3 成本控制
每次 LLM 调用都花钱，Agent 的循环可能产生大量调用：
- 限制最大迭代次数
- 使用更便宜的模型做简单任务
- 缓存重复查询的结果

### 6.4 可观测性
Agent 的决策过程是黑盒，需要：
- 记录每一步的 Thought/Action/Observation
- 可视化执行流程
- 监控 token 消耗和延迟
